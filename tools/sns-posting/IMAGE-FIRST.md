# お店の画像を主役にする共有処理

## 2026年10月27日の修正

以前の `photo-brand.js` は出力幅1080に対し、写真の高さも1080で制限していた。
1080×1920の写真は約608×1080まで縮まり、1080幅のキャンバスの左右に余白ができていた。

修正後は写真の幅とキャンバスの幅を一致させる。1080×1920の写真は1080×1920で配置する。
元の縦横比と写真全体を保持し、DXバナーは下に独立して配置する。
極端に縦長な入力にはキャンバスの上限を適用し、無理な切り抜きはしない。

`post-share.js` は画像を準備してから共有ボタンを有効にする。
クリック時には準備済みのJPEGファイルだけを `navigator.share({files})` に渡す。
記事の文章を画像へ描き込まず、URLを画像の代わりとして渡さない。
投稿文とDXリンクのコピーは画像共有を待たせない。コピー失敗時も画像共有を止めない。
コピー用の独立ボタンも常に表示する。

写真の保存と、ファイル共有を使えない端末での案内を残す。
複数枚をまとめて共有できない場合は、1枚ずつ渡すボタンを表示する。
合成が失敗した場合は元のJPEG写真を使う。
LINE向けの既存の特典OGPページと `benefit-share.js` は変更していない。

これはiPhoneの実機やFacebookアプリを操作した結果ではない。
共有APIの成功はFacebookへの投稿完了を意味しない。
Facebookのフィード上の表示比率や切り抜きは、このコードだけでは保証できない。
写真添付のタップ先はSNSの写真表示であり、DXへの入口は投稿文のURLになる。
