# お店めぐりDX 導線・ページ追加 設計図
版：1.3 / 2026年11月19日（日本時間）
対象：ichirohns-jpg/ShikiConcierge-18 の omise-demo/

## 守る方針
既存の写真・動画・投稿・特典・管理・共有を保持し、移動を共通化する。トップのお店一覧は1つだけ。色は既存の紫系とSNS固有色を維持する。1ページ追加のたびに全体を作り直さない。

## 利用者の流れ
- トップ index.html → #shops の一覧 → 各店の固定紹介URL → 写真 / 店舗情報・SNS / 紹介・共有 → お店一覧。
- 投稿一覧 timeline.html → article.html?id=投稿ID → 対象店舗の紹介。記事の戻り先はDX内の参照元（投稿一覧・お得情報・店舗）。SNS等からの直接訪問では投稿一覧。
- お得情報 deals.html → 特典詳細 / 投稿記事 → 対象店舗。特典の利用条件と掲載状態は現在の内容を維持する。
- ふじこのお知らせ fujiko-news.html → 紹介している店舗 → お店一覧。
- 投稿・編集 owner.html → 投稿 / 自分の記事 / 基本情報 / 写真 → 公開画面。ログイン・保存APIは変更しない。

## 共通ナビゲーション
画面上：お店一覧 / 投稿・編集（固定せず本文と一緒に流れる）。画面下固定：トップ / お店を探す / 投稿を見る / お得情報。今いる項目は紫で表示。下部は安全領域に対応し本文に余白を確保。タップ領域は原則48px以上。ページ内リンクは上部バーに隠れない余白を確保。
店舗紹介には #intro の副題直後にページ内メニューを置く。写真と紹介、店舗情報・SNS、共有を1タップで開く。既存の店舗投稿・特典リンクも維持。長い写真群より上に入口を置く。

## ファイルの役割
- dx-nav.js：共通上部・下部メニュー、現在地、戻り先、店舗ページのページ内メニュー。既存3店の対応に加え、body.social-profile と #intro h1 がある新規店も自動認識する。
- dx-nav.css：共通導線のサイズ、固定位置、安全領域、重なり回避。既存デザインの末尾で導線だけを上書きする。
- index.html：sample と shopPages が一覧の初期データと固定URL対応。GAS応答のうちsampleに登録済みの店舗だけを既存データに統合する。既存sampleの順番は変えない。
- shops.json：既存3店の紹介データ・slug・画像・共有URL。現状は全一覧の単一マスターではない。勝手に一元化・移行しない。
- posts.js：登録済み店舗の投稿・記事・対象店舗へのリンク。IDから紹介URLへ対応する。未登録の店舗には投稿枠を作らない。
- post-share.js / fujiko-share-locations.js：既存の権限付き共通共有。ログイン名義・公開範囲を維持。
- owner.html / owner-info.html / owner-scenes.html / owner-runtime.js：店主用の管理。GAS・JSONP・DB列を導線修正のついでに変更しない。

## 共有の固定ルール
ハートネット志木 / ふじこの両方を維持する。名義を選ぶ → 紹介文と対象店舗名を確認・修正 → コピーまたはSNSへ。ふじこ画像を別キャラに変えない。主要共有・コピーボタンは紫地・白文字、Facebook青・LINE緑・X黒。未ログイン時の既存権限を勝手に変えない。
共有URLは対象の店・記事に直接開く固定URL。表示確認用の ?v= はSNSの正規共有URLに混ぜない。canonical / OGP / Twitterメタ情報は対象の店名・説明・GitHub固定画像で一致。既存短縮共有URLは勝手に置き換えない。SNSの最終投稿は利用者が確認して行う。

## 1ページ追加の手順
1. 店名・住所・連絡先・写真の出所・掲載確認状態・固定slugを確定。未確認の営業時間やキャンペーンを作らない。
2. 最新の既存ページから構造を引き継ぐ。body.social-profile と #intro / #photos / #information / #share を付け、h1に固有の店名。記事を作る場合はAGENTS.mdの動画直下の店名ルールを適用。
3. 共通 dx-nav.css / dx-nav.js を現在と同じバージョンで読み込む。既存の配色を引き継ぐ。
4. index.html の sample 末尾に一意の公開IDで追加し、shopPages に固定URLを登録。既存配列の順番・写真の追加処理を変えない。#shopsの検索対象に店名・分類・住所を含める。
5. shops.json に追加が必要かを確認。店主投稿へ接続するなら正式ID・管理登録を確認し posts.js の対応も追加。紹介だけなら既存の店主IDを流用しない。
6. 共有欄の両名義・対象店名・正規URL・画像を設定。既存の共通方式を使用し、二重初期化しない。
7. canonical / OGP / Twitter / sitemap-shops.xml の必要な追加を行う。既存ページURL・短縮URLは保持。
8. 一覧から入って各店へ、共有から固定ページへ、店舗から一覧へ往復する。375px程度・文字拡大・横はみ出し・固定メニューの重なりを確認。既存3店の投稿・特典も再確認。
9. 公開反映を確認して設計図の版・変更日・追加したID/URL・確認結果を更新。利用者にHTMLの貼り替えを依頼しない。

## 検証範囲
静的な内部ファイルリンク、共通JS構文、公開ページでの一覧・ページ内移動・投稿記事・特典・管理入口を点検する。テスト投稿やSNS送信は実行しない。iPhone Safari実機とSNS送信先での最終表示は別環境のため、検証済みと混同しない。
